# Placement and builder addendum

The platform stage **replaces** the old minimal platform probe; they cannot coexist as independently resident programs. Both code images begin at `0x34180400`, and the stage's reserved CODE interval extends through the old probe stack/mailbox at `0x34184000–0x341850ff`. Only the *new mailbox's own address* is different. A loader must halt/quiesce and replace the old probe before entering the stage. The stage remains separate from the SRAM model adapter at `0x34064000` and weights/activations at `0x34200000`/`0x34240000`. This corrects the potentially ambiguous placement sentence in the preserved README; the original README is not altered.

The original `build.py` invocation (`1eb4f7`, exit 1) stopped before any compiler command because the installed ordinary `arm-none-eabi-gcc` file has two hardlinks. Failure receipt `PLATFORM_STAGE_ACTUAL_01_FAILURE.json` is retained in the bring-up results root. No output directory or ELF was created, and no automatic retry was performed.

Additive `build_v2.py` changes only installed-tool identity capture/rechecking plus the declared tool-path list. It allows a canonical ordinary regular tool file with a positive original link count, uses O_NOFOLLOW and same-FD hash/stat bookends, and retains/checks that count later. It does not weaken the original single-link checks for sources, payload or owned output. The corresponding six driver/tool binaries and gcc-selected cc1/as/ld all use this domain. All actual compiler commands, source flags, target sequence and ELF layout checks are unchanged. A newly authorized attempt must use a new output directory, e.g. `platform_stage_actual_02`; no such run is claimed here.
